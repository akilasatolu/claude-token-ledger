どこを直すと減らせるか

減らせそうな量が大きい順です。緑の枠が、具体的な直し方です。量は、各項目の注記にある仮定で見積もった目安です。項目どうしで重なる分があるため、合計は出していません。例の行をクリックすると、下のグラフのそのやり取りに移動します。

    大きく減らせそうな項目は見つかりませんでした(全体の 0.5% を超えるものがありません)。

    全観点ランキング

      いつでも効く基本

      記録の数字に出てこなくても使える、減らし方のまとめです。上の項目で当てはまったものがなくても、習慣にすると効きます。

      会話の使い方6 項目

      会話が長いほど、毎回の送信が重くなります。短く保つのが、いちばん効きます。

      • 依頼ごとに会話を分ける終わったら /clear か新しい会話にします。前の依頼の内容を、次の依頼でも読み直さずに済みます。
      • 長くなる前に要約する区切りで /compact を実行します。「/compact 決まった仕様とエラーの原因だけ残して」のように、残す内容も指定できます。
      • 今どれくらい使っているか見る/context で、会話の中身の内訳を確認できます。何が大きいかが分かれば、直す場所が決まります。
      • 古い会話を、そのまま再開しない長くなった昔の会話を --resume で再開すると、その長さをまた読み直します。続きでなければ、新しい会話で始めます。
      • 1 つの会話に 1 つの目的別の話題は新しい会話にします。関係のない履歴が、毎回読み直されるのを防げます。
      • 短い質問は、新しい会話で長い会話の中で一言だけ聞くと、会話全体が読み直されます。ちょっとした質問は、別の会話で聞きます。

      指示の出し方8 項目

      最初の指示が具体的なほど、探し回りもやり直しも減ります。

      • 場所を具体的に書く「認証まわりを直して」より、「src/auth/token.ts の validateToken を直して」のほうが、探す回数が減ります。ファイルは @ を付けて指定できます。
      • 完成の条件を先に伝える「テストが通ったら完了」「この 3 項目が動けば完了」のように書くと、やり直しが減ります。
      • やる前に方針を確認する大きな変更は、実行の前に「やり方を 3 行で説明して」と頼みます。計画モード(Shift+Tab で切り替え)も使えます。
      • 触らない範囲を伝える「他のファイルは触らないで」と書くと、余計な読み込みと変更が減ります。
      • 1 つの依頼は 1 つの目的にあれもこれもと詰め込まず、目的ごとに分けると、会話を短く保てます。
      • 返答の長さを指定する「結論を 5 行で」「差分だけ見せて」と頼むと、返答のトークンが減ります。「詳しく」「徹底的に」は長くなります。
      • エラーは要点を貼るエラーは、前後 20 行ほどと、実行したコマンドを貼ります。全文の貼り付けは、毎回読み直されます。
      • 間違いに気づいたら、すぐ止めるEsc で中断して、言い直します。間違った方向の作業が、続くのを防げます。

      ファイルとコマンド7 項目

      読み込みと実行結果は、会話にそのまま積まれます。出力を絞るのが近道です。

      • ファイルは範囲を指定して読む「100〜200 行目だけ」「○○関数の部分だけ」のように頼みます。大きなファイルの丸ごと読み込みを避けられます。
      • 先に検索で場所を絞るGrep でファイル名だけを出させてから、必要なファイルを読みます。
      • コマンドの出力を絞る「最後の 20 行だけ」「失敗した行だけ」と頼みます。npm install や テスト実行は、出力が長くなります。
      • git の履歴は件数を絞るgit log は --oneline -20、git diff は --stat から見ます。
      • 同じものを読み直さない一度読んだ内容は会話に残っています。「さっき読んだファイルを使って」と伝えます。
      • 読ませたくないファイルを除くnode_modules、ロックファイル、ログ、生成ファイルは、設定(permissions の deny)で読み取りを禁止できます。
      • 大きなデータは要約を作らせるCSV やログは、全体を読ませずに、集計するコマンドの結果だけ見せます。

      調べものとサブエージェント5 項目

      広い調べものは、別担当に任せると、メインの会話が重くなりません。

      • 調べものは任せる「サブエージェントで調べて、結論を 5 行で報告して」と頼みます。調べた過程が、メインの会話に残りません。
      • 報告の長さを決める任せるときは、「結論と根拠のファイル名だけ」のように、返す内容を決めます。
      • 小さな確認には使わない1〜2 回で終わる確認は、メインで直接行うほうが軽く済みます。
      • 調べる範囲を狭める「このフォルダだけ」と範囲を指定します。
      • まとめて頼む複数のファイルや検索は、「まとめて並行して読んで」と一度に頼みます。送る回数が減ります。

      設定と環境5 項目

      毎回の送信に含まれる「土台」を軽くすると、すべてのやり取りが軽くなります。

      • CLAUDE.md を短く保つ毎回送られます。長い説明や古い情報は消して、守ってほしいルールだけを残します。
      • 使っていない MCP を止める/mcp で接続を確認して、使わないサーバーは外します。接続しているだけで、ツールの一覧が毎回送られます。
      • 毎回の指示は CLAUDE.md に何度も書く前提は、一度だけ書きます。ただし短く。
      • 用途に合わせてモデルを選ぶ調べものや簡単な修正は軽いモデル、難しい設計や原因調査は重いモデル。/model で切り替えます。
      • 不要なプラグインを外す使っていない拡張は外します。土台が軽くなります。

      待ち時間と使い回し4 項目

      約 5 分あくと、使い回し(キャッシュ)が切れます。

      • キリの良いところまで進める席を離れる前に、作業をひと区切りさせます。続きは新しい会話にすると、無駄がありません。
      • 作業の途中で設定を変えないCLAUDE.md やツールの設定は、依頼の切れ目で変えます。途中で変えると、そこから先の使い回しが効かなくなります。
      • 長い中断のあとは要約してから/compact で短くしてから再開します。古い会話を、そのまま送り直さずに済みます。
      • 使い回しの割合に安心しない割合が高いのは正常ですが、量は数えられます。会話を短くすることが、減らす基本です。

      分かったこと

        用語の説明
        トークン
        Claude が読んだり書いたりする文章の量の単位です。日本語ではおよそ 1 文字が 1〜2 トークンです。
        やり取り
        Claude に 1 回送って、1 回返事をもらうまでの流れです。1 つの依頼の中で、何度も繰り返されます。
        会話の長さ
        1 回のやり取りで Claude が読み直す、これまでの会話の総量です(コンテキストとも呼びます)。やり取りのたびに毎回全部が送られるため、長いほど 1 回あたりの消費が増えます。
        使い回し(キャッシュ)
        前回と同じ内容を、Claude が覚えておく仕組みです。使い回せた分は速く、安く処理されます。ただし、この画面ではトークン数としては数えます。
        要約(/compact)
        長くなった会話を、短い要約に置き換える操作です。自動で行われることもあります。トークンは減りますが、細かい経緯は忘れやすくなります。
        サブエージェント
        調べものなどを、別の担当に任せる機能です。任せた側の会話は別に数えられます。

        トークンは、記録に残っている使用量(新しく送った分、使い回した分、Claude の返答)をそのまま数えています。最初に表示しているのは、作り物のサンプルデータです。減らせる量は、実際の会話の長さの増え方から計算した目安です。「席を離れていた」判定は、5 分以上のあきを基準にしています。使い回し分が利用制限にどれだけ数えられるかは公開されていないため、ここでは区別せずに数えています。
